## Project

**qnx-buildfile-lint** — a host-based linter and validator for QNX mkifs
buildfiles, with an IFS image inspector.

- **Category:** Developer Tooling & Host Tools
- **Repo (to be created by the coordinator):**
  `https://github.com/gemmaworks/qnx-buildfile-lint`
- **Licence:** MIT
- **Demo video:** `demo/qnx-buildfile-lint-demo.mp4` (72 s, 1920×1080,

- **QNX version targeted:** QNX SDP 8.0 / QNX Everywhere (8.0.x);

## Submission text (Devpost description)

> `mkifs` fails late: a typo in a QNX buildfile is usually discovered only
> when the image build breaks — or worse, when the target does not boot.
> qnx-buildfile-lint catches the mistake on the host, before `mkifs` ever
> runs, with the exact line, a rule code, and a fix hint. It also inspects
> built `.ifs` images the way `dumpifs` does — startup header, image
> header, directory entries, and both trailer checksums — so a corrupt or
> truncated image is caught before it is flashed.
>
> The linter understands the real `mkifs` grammar: attribute blocks,
> sticky attributes, `target=host` mappings, inline files, `?`-conditional
> attributes and `${VARIABLE}` expansion. It validates all QNX 8.0
> attributes, including the new ones (`+dupignore`, `ifs_csa`, `sha512=`),
> the `virtual=[cpu,]bootfile` CPU/bootfile compatibility table
> (`bios` is x86_64-only, `raw` is aarch64le/armle-v7-only), `image=`/`ram=`
> address spaces, `perms=` (octal and symbolic modes), `mtime=`,
> `sha256=`/`sha512=`, `compress=` (zlib is not bootable), `type=link`
> rules, and `keepsection=` defaults. It checks the boot sequence
> (bootstrap first, `startup-*` … `procnto`, `+optional` illegal there),
> parses startup scripts as `procnto` does (not as shell — no redirection,
> pipes, loops or wildcards), and cross-checks that every command the
> script starts is actually in the image. With `--check-host` it also
> verifies host files exist and match their `sha256=`/`sha512=`/`cksum=`
> hashes, and expands `[+include]` with cycle detection.
>
> The IFS inspector parses the on-disk format (`sys/startup.h`,
> `sys/image.h`): startup header signature `0x00FF7EEB`, image header
> (`imagefs`), directory entries (files, directories, symlinks, devices),
> and both trailer checksums (negated 32-bit word sum). zlib-compressed
> images are decompressed and listed; LZO/UCL are reported honestly as
> unsupported. `--extract` unpacks an image like `dumpifs -d`.
>
> 79 rules (`QNX100`–`QNX510`), text and JSON output, `--strict` for CI,
> exit codes 0/1/2. Python 3, standard library only, no dependencies.
> 87 tests pass. Includes a 20-minute codelab
> (`docs/CODELAB.md`): write a Raspberry Pi 4 buildfile, lint it, fix
> each finding, inspect the resulting image — no QNX installation needed.

## How to build / run (for the Devpost "Build & run instructions" field)

```sh
git clone https://github.com/gemmaworks/qnx-buildfile-lint.git
cd qnx-buildfile-lint
./qnx-buildfile-lint examples/x86_64-bios.build   # clean
./qnx-buildfile-lint examples/bad/bad-duplicate.build
./qnx-buildfile-lint ifs demo/demo.ifs
./run_tests.sh   # 87 tests, stdlib unittest
```

Optional, with QNX SDP 8.0 installed and `qnxsdp-env.sh` sourced:

```sh
mkifs -v examples/x86_64-bios.build /tmp/test.ifs
./qnx-buildfile-lint --check-host examples/x86_64-bios.build
./qnx-buildfile-lint ifs /tmp/test.ifs
qemu-system-x86_64 -kernel /tmp/test.ifs -m 512 -serial stdio
```

## How it was made

Built with AI assistance (the linter's rule set was derived from the QNX
SDP 8.0 `mkifs` documentation and the `sys/startup.h` / `sys/image.h`
on-disk layout as documented by the MIT-licensed `qnx-ifs` crate).
No QNX/SDP account was needed: the tool is host-based and was developed
and tested against self-written example buildfiles and synthetic IFS
images generated by the tool's own builder (`qnx_buildfile_lint/ifsgen.py`).
